# AGENTS.md

Guidance for agents working in the `ludex` repository: a local-first catalogue and
recommender for Linux-playable games, written in Nim.

`docs/DESIGN.md` is the authoritative design document (data model, source survey,
measured facts, roadmap). Read it before large changes. This file complements it with
the working knowledge that is *not* obvious from reading a file or two.

## Essential commands

```sh
# Build the CLI
nim c -o:bin/ludex src/ludex.nim

# Build the native GTK4/libadwaita window
nim c -o:bin/ludex-ui src/ludexui/app.nim

# Build the window with its self-capture harness (see "Seeing the window" below)
nim c -d:ludexSnapshot -o:bin/ludex-snap src/ludexui/app.nim

# Test: compiles and runs every tests/t*.nim, deterministic and offline
nim c -r tests/tester.nim
nim c -d:release -r tests/tester.nim
nim c -d:danger -r tests/tester.nim
```

All three test configurations are expected to pass. Run all three after touching core
logic; release/danger can surface different behavior.

```sh
# Dependencies (see below). nimble is NOT used.
atlas install     # clones deps/brian and deps/owlkettle
atlas pin         # records the exact commit in atlas.lock

# Generate API docs for a module
nim doc --outdir:/tmp/ludexdoc src/ludexcore/parse.nim
```

There is no formatter or linter configured. Do not add one.

## Dependency workflow (non-standard)

- Dependencies are managed by **Atlas**, not nimble. `nimble` is not installed and
  `nimble install`/`nimble build` will not work. `requires "..."` in `ludex.nimble` is
  read by Atlas.
- `deps/` is generated and git-ignored; `atlas.lock` is committed for reproducibility.
- `nim.cfg` has two sections. The **user section** (`--path:"src"`, `--hints:off`,
  `--define:ssl`, and the window's `--define:adwminor=4` / `--define:gtkminor=10`) is
  hand-written. The **Atlas config section** between the
  `begin Atlas config section` / `end Atlas config section` markers is generated by
  Atlas and must not be hand-edited; Atlas rewrites it on `atlas install`.
- `-d:ssl` is required: every enrichment source is HTTPS. A CLI built without it fails
  every request at runtime. Do not remove it.
- The window targets libadwaita 1.4 and GTK 4.10 because owlkettle only exposes
  `AdwToolbarView` and `AdwHeaderBar`'s title widget when the target minor versions are
  declared. `nim.cfg` carries both defines, so the documented `nim c` command keeps
  working; removing them deletes widgets `app.nim` depends on.

## Architecture and layering

Strict one-way dependency: pure core ← ingest ← front ends. The CLI and the UI are
siblings: neither imports the other.

| Layer | Path | Rules |
|---|---|---|
| Core | `src/ludexcore/` | Pure. **No I/O, network, threads, or FFI.** String in, string out. |
| Source decoders | `src/ludexcore/sources/` | Pure. Turn a recorded response body into facts. |
| Ingest | `src/ludexingest/` | Owns HTTP, cache, rate limiting: `enrich.nim` for facts and `artcache.nim` for pictures. |
| CLI | `src/ludex.nim` | Owns the file system and the network. |
| UI | `src/ludexui/` | owlkettle/GTK4. `catalog.nim` owns the file system, `present.nim` is pure, `app.nim` is layout only. No network: enrichment and pictures are CLI jobs, the window reads what they wrote. |

- `ludexcore` must not `import std/os`. This is why the tests need no fixtures on disk
  and run offline. If you need a file read, do it in `src/ludex.nim` or
  `src/ludexingest/` and pass strings down.
- `client.nim` is the only module that performs network I/O (`std/httpclient`).
- JSON is handled **exclusively by `brian`** — never `std/json`, never a DOM. `brian`
  decodes straight into Nim types and encodes straight into a string.
- `ref object` is used only where identity matters (the in-memory game index, UI state).
  Everything else is value semantics; absent data is `Option[T]`.

### `brian` gotchas (these fail silently, not loudly)

1. **Reader declaration order is load-bearing.** `brian` resolves nested readers via
   `mixin` at the point of instantiation, so `readJson(Outer)` must be declared *after*
   the readers for every type it contains. Order the readers innermost-first. Violating
   this can produce an empty record with no error. This is documented in the module docs
   of `steamstore.nim` / `store.nim`.
2. **Wire names are not Nim names.** Store API payloads are `snake_case`
   (`price_overview`, `is_free`, `release_date`) and `type` is a Nim keyword, while the
   struct fields are camelCase. Every `readJson` must name each field explicitly and
   match it; relying on name matching silently yields empty data. `isKnown` assertions
   exist to catch exactly this.
3. **Float parsing is one ULP off** for values like `0.3`, `0.6`, `0.7`, `92.8`. All
   stored floats are rounded to the precision the source justifies via
   `models.roundTo` / `roundTierScore` / `roundReviewPercent`, on both read and write, so
   the stored form is canonical and diffs stay clean. Do not store unrounded floats.
   Config floats (not stored data) are compared with a tolerance in tests.

### `owlkettle` gotchas (the UI's equivalent of the brian list)

1. **A top-level widget in a `gui:` block may not carry an adder pragma.** `Box {.expand:
   false.}:` fails with "the top-level widget in a gui tree may not have an adder": the
   pragma names the *parent's* adder, and the root has no parent. Drop the pragma on the
   root and put the constraint on the children instead.
2. **Pragma arguments use `:`, field assignments use `=`.** `Button {.expand: false.}:
   text = "x"` is correct; `{.expand = false.}` is a parse error. They look alike and only
   one compiles.
3. **`{.expand: false.}` only exists where the parent's adder declares it.** `Box`,
   `Card`-style containers and similar accept it; a `ScrolledWindow`, `Window`, `Button`
   or `HeaderBar` does not, and the error is "unknown named parameter: expand".
4. **Do not destructure tuples in a `gui:` `for`.** `for (a, b) in items: Button: text = a`
   fails to resolve the generated `valText = a` assignment. Iterate one variable and index
   it (`for item in items: ... text = item[0]`); that works.
5. **State mutates in place and the event redraws.** The `AppState` is a ref object that
   lives as long as the app, so `app.catalog.taste.rate(...)` inside a callback persists and
   the following redraw re-runs `view`. Fields are only copied from the widget during
   `buildState`/`updateState` when the view *sets* them, so a state field the view never
   assigns keeps its value.
6. **`ffDecimal` with a precision of zero still emits the dot** (`92.` not `92`). Use the
   integer rounding in `present.formatPercent` for whole percents.
7. **Row labels are Pango markup, and a parse failure blanks them.** libadwaita parses
   `AdwPreferencesRow:title`, `AdwActionRow:subtitle` and `AdwStatusPage:description` as
   markup (its `use-markup` default is `TRUE`) and *silently blanks* the label on a parse
   error, leaving only a `Gtk-WARNING`. Every catalogue-derived string that reaches a row
   must pass through `present.escapeMarkup` first: a tag named "Point & Click" is exactly
   the value that breaks it. `AdwPreferencesGroup` title/description, `AdwWindowTitle`, an
   `AdwAvatar`'s text and a plain `Label` are *not* markup, so escaping there prints the
   entities instead.
8. **An adder pragma belongs to the parent, so a helper proc cannot carry one.** A `proc`
   that returns `gui: Box {.expand: false.}: ...` hits gotcha 1, because the pragma describes
   how the *caller* adds the widget. Leave `{.expand: false.}`, `{.hAlign: ...}` and
   `{.vAlign: ...}` off the returned tree and put them on the `insert(...)` at the call
   site: `insert(thumbFrame(app, release)) {.expand: false, hAlign: AlignStart.}`.
9. **`AdwActionRow` has no prefix adder.** `adw_action_row_add_prefix` is bound but not
   exposed, so a row that leads with a picture cannot be an `ActionRow`. Build a plain `Box`
   inside a `ListView`/`ListBox` instead; the row's own padding and the list's separators
   come from the list, not from the row widget.
10. **`MenuButton`'s `icon` is its child.** `icon = "..."` is implemented as
    `valChild = Icon(...)`, and the second `add` becomes the popover, so the icon must be
    assigned *before* the `Popover`. Write the popover first and it takes the child slot and
    the icon is silently lost.
11. **`ModelButton.shortcut` is display-only.** It sets the `accel` property, not a shortcut
    controller, so unlike `Button.shortcut` it does not make the key work. Put real
    shortcuts on a `Button` and leave the `ModelButton` without one rather than advertising
    a key that does nothing.
12. **A `Box` child expands by default.** `adder add {.expand: true, hAlign: AlignFill,
    vAlign: AlignFill.}`, so `insert(x)` and every nested widget block grow to fill the
    remaining space. That is what stretches a single button into a giant pill when the
    rest of the page is short, and what pushes a grid to the bottom of the window when a
    `Box` header row above it was written as `Box(orient = OrientX, spacing = 12)` without
    a pragma. Put `{.expand: false.}` on each child that should keep its natural size, and
    state the intent explicitly rather than trusting the default.
13. **Extending a `renderable` does not inherit its `beforeBuild`.** `renderable X of Y`
    must create the widget itself (`state.internalWidget = gtk_<y>_new()`), or every
    property call lands on a nil widget and GTK logs a wall of `Gtk-CRITICAL` assertions.
    `widgets.nim`'s `BoundedLabel` is the worked example.
14. **`FlowBox` sizes homogeneous cells from the widest child.** One long game title makes
    every tile that wide, collapsing a four-column grid to two. A plain `Label` has no
    width cap and Owlkettle exposes no `max-width-chars`, so `widgets.nim` adds
    `BoundedLabel`; use it for anything in a grid whose text is unbounded.
15. **A hand-built popover needs the `.menu` style class.** Adwaita's menu row padding,
    radius and hover live in `popover.menu modelbutton`, so a `Popover` without
    `StyleClass("menu")` renders its `ModelButton`s as bare buttons on a plain surface.
    Put the items in a `Box` inside the styled popover and separate groups with a
    `Separator` (`popover.menu separator` carries its own vertical margin).
16. **`ModelButton` parses `_` mnemonics itself.** It has no `use-underline` property;
    `GtkModelButton` feeds the text to a mnemonicking label, so `_Open Catalogue…`
    renders correctly and a custom renderable to enable underlining is unnecessary.
17. **A `Button`'s shortcut cannot change after it is built.** The widget's `update` hook
    asserts `state.shortcut == widget.valShortcut`, so pointing one button at two
    different keys depending on state crashes a debug build (and silently keeps the old
    key in a release one). Give each shortcut its own button, or keep it constant.
18. **Do not reparent a viewable's content between widget types.** Swapping the content
    child of a `ToolbarView` between two different renderables makes Owlkettle reuse and
    then disconnect a state whose event was never connected, which trips
    `assert event.handler > 0` in `widgetutils.nim`. Both the viewer swap and the header's
    changing button survive this today, but keep the branch shallow.
19. **`ModelButton.icon` is not a checkmark.** Owlkettle implements `icon` by setting GTK's
    `iconic` *as well as* the icon, and `GtkModelButton` in iconic mode hides the label:
    `ModelButton: icon = "object-select-symbolic"` renders a lone tick with no text. A real
    checkable menu row is a `GtkModelButton` with `role = check` and `active`, which keeps
    the label and draws GTK's own indicator. `widgets.nim`'s `CheckedMenuItem` does this
    (`renderable ... of ModelButton`, its own `beforeBuild` per gotcha 13, plus an `active`
    property hook). A bonus: `GtkModelButton` sets `keep_open` for any non-normal role, so
    tapping one filter leaves the popover open for the next.
20. **An icon name must exist in the installed theme, and `view-filter-symbolic` does
    not.** There is no funnel anywhere under `/usr/share/icons` here, and a missing name
    silently renders GTK's blank "broken image" placeholder, which reads as a blank
    button. Check before using a name:
    `find /usr/share/icons -name '<name>.svg'`. In use today: `view-more-symbolic` for the
    filter menu (GNOME's secondary-menu icon), `action-unavailable-symbolic` for the
    filtered-to-nothing page, `starred-symbolic` for a loved tile.

## Showing pictures at their own size

The viewer shows an image with `ContentScaleDown`, never `ContentContain`, so a 600px
screenshot is not blown up to the window width. It also loads the file at its native size
(`app.picture(path, 0)`) rather than reusing the 320px thumbnail the strip decoded, and
`ludexcore/art.nim` prefers the store's full-size URL so there are pixels to show.

## Seeing the window without a desktop

There is no screenshot tool here, so the window renders itself:

```sh
nim c -d:ludexSnapshot -o:bin/ludex-snap src/ludexui/app.nim
LUDEX_SNAPSHOT=/tmp/game.png LUDEX_SNAPSHOT_SIZE=1180x900 \
LUDEX_SNAPSHOT_APPID=1264280 LUDEX_SNAPSHOT_DELAY=1600 ./bin/ludex-snap   # light: add LUDEX_SNAPSHOT_LIGHT=1
```

`LUDEX_SNAPSHOT_QUERY` opens the search field instead. `LUDEX_SNAPSHOT_VIEWER=<index>` opens
the picture viewer, `LUDEX_SNAPSHOT_CLOSEVIEWER=1` also steps and reopens it (which
exercises the update path over a changing tree), `LUDEX_SNAPSHOT_HOVER=1` forces
`GTK_STATE_FLAG_PRELIGHT` on the first grid item, and `LUDEX_SNAPSHOT_MENU=<n>` pops up the
*n*th header menu counting from one (1 is the primary menu, 2 the filter menu), so hover and
menu styling are visible in a capture. A popover lives on its own surface, so the harness
captures the popover of the button it opened rather than the window: with two menu buttons
"the first popover in the window" is not necessarily the open one. `LUDEX_SNAPSHOT_FILTER`
presets the view's filters from the command line: `runs`, `deck` and `unjudged` toggle those
switches and anything else is treated as a genre name, so
`LUDEX_SNAPSHOT_FILTER=runs,Indie` captures a filtered library and
`LUDEX_SNAPSHOT_FILTER=Stealth` captures the nothing-matches page. The capture waits one
extra frame after the scene is applied; without it the first frames after a map can be
captured before the content slot is laid out, which was showing up as occasional captures
of a page the state said was not there. The
build is inert without the define; `src/ludexui/snapshot.nim` and the
`applyScene`/`readSceneEnv` hooks in `app.nim` exist only under `-d:ludexSnapshot`, so the
shipping binary carries none of it. Inspect the PNG downscaled (the full-size image
exceeds what `view` accepts).

## Filtering the collection

`ludexui/catalog.browse(catalog, query, filters)` is the one entry point: it searches and
filters in the same pass, so a new filter cannot accidentally apply to one view of the
collection and not another. Adding one means touching four places, all of which fail
silently if you skip them:

- `catalog.Filters`: add the field, and the doc comment saying what evidence answers it.
- `catalog.keeps`: read the field. An absent fact is never a yes, as `runsOnLinux` shows
  (no tier, no Linux build, no native build means "not a match", not "maybe").
- `app.filterMenu`: add the row. The three switches use `CheckedMenuItem`
  (`toggleFilter`/`FilterKind`); genres are generated from `catalog.genreOptions()`, which
  offers only genres at least three games carry, most common first.
- `app.filtersActive`/`filterCount`: otherwise the summary line, the "Clear Filters" row and
  the nothing-matches page all keep claiming nothing is filtered.

Several picked genres mean *either*, not *all* (`matchesGenre`), because that is how a
multi-select is read. `tests/tcatalog.nim` pins the semantics: a game whose genres never
arrived is not a genre match, an unknown genre matches nothing rather than everything, and
`vLater` is a deferral rather than a verdict so it stays visible under "Hide games I've
rated".

## Data formats and conventions

- The store is **newline-delimited JSON**, one game per line, compact. Absent fields are
  **omitted**, never written as `null`: absence is a fact in this catalogue, not a
  placeholder. Ordering is by app id so files are stable and diffable.
- Enums have **explicit string spellings** (`ptGold = "gold"`) so `$`/`parseEnum`
  round-trip against the JSONL. Reading an unrecognized enum spelling fails that line
  rather than guessing.
- **`PlayTier` and `AntiCheat` are ordered worst-to-best on purpose** so a threshold
  test (`tier >= ptGold`) fails closed. `ptUnknown` and `acUnknown` sort lowest. If you
  add a member, place it with this ordering in mind; a filter that forgets to special
  case unknown would otherwise rank the least-known games as the best.
- **`SourceId` is a closed set: add members, never reorder** (the order is a wire
  format).
- Every enriched value is a `Fact[T] = (value, source, fetchedAt, confidence)`. A price
  or score without a timestamp is a claim about the past presented as the present; keep
  provenance.
- Batch boundaries (`decodeLines`, `decodeTaste`, the enrich inner loops) record a
  per-line/per-game failure as `"<line>: <reason>"` and keep going; they never abort the
  run on one bad row. Functions that cannot raise are marked `{.raises: [].}`.
- Multi-call sources (Steam makes three calls per game) attempt each call independently:
  one failing call must not discard the other good answers. `RunStats.partial` tracks
  partial answers.
- The merge rule is "newer fact replaces older, everything else is left alone", so
  re-running one `--source` is safe and a source staying silent never deletes another
  source's facts.

### Default paths (CLI)

`data/enrichment.jsonl` (`--out`/`--enrichment`), `data/cache` (`--cache`),
`data/ratings.jsonl` (`--ratings`), `data/weights.json`, `data/art` (`--art`). `data/` is
generated and git-ignored.

### Cache format

One file per URL, named from the **sanitized URL** (readable, not hashed), containing a
status line, a blank line, then the body:

```text
HTTP/1.1 200

{"tier":"platinum","score":0.71,"total":31}
```

The status is cached because a `404` is an answer worth remembering (ProtonDB returns
`404` for "nobody reported this game"), not a failure. A corrupt cache file is a miss,
not an exception. `--offline` never opens a socket and fails on a cache miss; the tests
use this. Any non-`2xx`/`404` status is returned to the caller; only `429` and `5xx` are
retried with backoff. `FetchError` is the client's error type; `Defect` is re-raised so
a programming bug is never recorded as a source outage.

Per-source default request delays are in `enrich.defaultDelayMs` (ProtonDB 250 ms,
Steam 1600 ms because the store allows ~200 req/5 min, SteamSpy 1200 ms, AWAC 0 ms
because it is a single request). `--delay` overrides.

### Pictures

The JSONL stores image **URLs**; the bytes live in `data/art/<appid>/` and are written by
`ludex art`, which uses the same client, cache and rate limit as `enrich`. The names are
the contract between the writer (`ludexingest/artcache.nim`) and the reader
(`ludexui/catalog.nim`), so both call `ludexcore/art.nim` rather than agreeing informally.
Three kinds of file live in one directory: `background.*` is the store's wide page art
(1438x810 and up), `header.*` is the 460x215 list image, and `shot-NN.*` are the
screenshots. The detail page's banner prefers the background because the header is too
small to draw large; the strip and the viewer only ever use the shots.
Screenshots are downloaded at `path_full` (1920x1080) with `path_thumbnail` (600x338) as
the fallback, never both, because the window's viewer shows one at its own size. A cache
written when the thumbnail was preferred keeps the same file name, so refreshing it needs
`ludex art --refresh`. Full-size pictures are roughly ten times the bytes of a thumbnail,
and the response cache holds a second copy of every body; `ludex art --limit` bounds a
sweep, and `data/cache` is disposable.

`mergeSteamFacts` **enumerates every field by hand**, so a field it does not name is
dropped silently: the run reports success and the fact never reaches the store. `art` was
added to the model, the codec and the merge in the same change for that reason, and
`tests/tenrich.nim` has a regression block (`art_survives_a_merge`) that fails if a field
is forgotten again. Adding any field to `SteamFacts` means touching all three.

## Parsing rules (fragile; read before touching `parse.nim`)

- The parser anchors on the `jc141` marker, then walks metadata fields **inwards from
  the right**, matching by pattern (build id, version, language token, runtime) and
  **never by position**. Field order varies in real data.
- It must **stop with at least one field left**: titles like `FEZ`, `OFF` and
  `1000xRESIST` are indistinguishable from ISO language codes, so without that floor the
  walk eats the title.
- Never `split(" - ")` the title naively: large titles contain `" - "`
  (`Disco Elysium - The Final Cut`).
- `MULTi6` is a count, not a set; it stays verbatim in `langToken` and is not expanded.
- `0 B` size means unknown and is stored as absent, never as zero.
- `tests/fixtures/listing-table.md` is a verbatim upstream copy. `tests/tparse.nim`
  asserts its exact shape (1998 games, 1545 app ids, runtime split 1456/365/16/161,
  etc.). If a parser change moves those numbers, that is a deliberate decision, not an
  accident to discover in production.

## Tests

- `tests/tester.nim` auto-discovers and runs every `tests/t*.nim` (except itself).
  New tests must be named `t*.nim`. Compiled test binaries land next to the sources and
  are git-ignored via the `/tests/t*` + `!/tests/t*.nim` rules in `.gitignore`.
- `tests/config.nims` adds `src/` to the search path, so tests import `ludexcore/...`
  and `ludexingest/...` directly.
- **No test touches the network, ever.** Decoder tests run against recorded real
  responses in `tests/fixtures/{protondb,steam,steamspy}/` plus `awac-games.json`.
  Ingest tests seed a response cache and run the client in offline mode, exercising the
  whole path deterministically.
- Follow the existing pattern: capture real API JSON into a fixture, assert the decoded
  fields, and include a regression assertion for any shape real data forced (e.g. `null`
  prices, empty-array `tags`, `success: false` with no `data`).
- Do not fix unrelated pre-existing test failures; report them instead.

## CLI conventions

- `src/ludex.nim` has its own `parseArgs` (not `parseopt`'s sequence overload), because
  those yields the flag and its value as separate tokens. It accepts `--name value`,
  `--name=value`, and bare flags. Commands: `parse`, `enrich`, `list`, `show`, `rate`,
  `pick`, `why`, `weights`, `help`.
- `requireOption` and friends call `fail(...)` which prints the usage text to stderr and
  exits; user errors never raise.
- `list --tier` is a threshold (`tier >= value`) because tiers are a scale.
  `list --anticheat` takes a comma-separated **set** of exact statuses because
  `broken`/`denied` and `running`/`supported` are different states, not points on a
  scale. That asymmetry is deliberate; keep it.
- `enrich --source anticheat` is one request for the whole dataset, so `--limit` has
  nothing to limit and is ignored. The usage text says so.

## Style

- Every module starts with a `##` doc comment explaining *why* (decisions, traps), not
  just what. Match that when adding modules.
- Nim stdlib style: `camelCase` procs/fields, `PascalCase` types, enums with
  `explicitString = "value"` spellings, `func` for pure work, `Option[T]` for absent
  values.
- Public API surface is narrow; helpers and orchestration stay private.
- Do not invent a second config format: tunable recommender weights are the JSON written
  by `ludex weights --out` and read by `--weights`.

## Scope boundaries

- No torrent/download automation or acquisition client. The listing row keeps its
  source reference as opaque provenance only.
- No browser/Nim-to-JS build. The target is a native executable (`nim c`); the UI is
  `owlkettle` (GTK4/libadwaita), which needs `gtk4` and `libadwaita` shared libraries at
  build and run time (`pkg-config` is used by owlkettle's bindings to link them).
- SteamDB and Metacritic are deliberately excluded (no API / anti-scraping). Critic
  scores come second-hand from IGDB/RAWG on demand.
